# 🏰 Project Architecture — Harry Potter Page

> Full documentation of the architecture, file structure and details of every component of the application.
> Last review: November 2026

---

## 1. Project Overview

**Hogwarts Mistery** is a CRUD-style SPA (Single Page Application) for managing Harry Potter characters: list them, view their details, create, edit and delete them.

| Aspect | Detail |
|---|---|
| **Main stack** | React 19 + Vite 8 |
| **Routing** | React Router DOM v7 |
| **Styling** | Bootstrap 5.3 (loaded via CDN in `index.html`) + custom CSS per component |
| **Alerts / popups** | SweetAlert2 |
| **Language** | JavaScript (JSX), no TypeScript |
| **Package manager** | pnpm (with `pnpm-workspace.yaml`) |
| **Data source** | `src/data/Characters.json` (local copy of the characters JSON, imported with an alias in `Service.js` — the fake API `hp-api.onrender.com` was suspended) |
| **Network simulation** | Simulated CRUD with `setTimeout` (500ms in `GetAll`, 300ms in the rest) |
| **Global state** | `useState` in `App.jsx` (no Redux, no Context) |
| **Deployment** | GitHub Pages → `https://t1629.github.io/Harry-Potter/` |
| **Base path** | `/Harry-Potter/` (set in `vite.config.js` and `main.jsx`) |

### Conceptual architecture (layered)

```
┌─────────────────────────────────────────────────────────┐
│  ENTRY LAYER:      index.html  →  main.jsx              │
├─────────────────────────────────────────────────────────┤
│  ROUTES / GLOBAL STATE LAYER:  App.jsx                  │
│  (declares routes and owns the "characters" state)      │
├─────────────────────────────────────────────────────────┤
│  VIEW LAYER:        src/page/*  (Home, List, Read, ...) │
│  receive "characters" and "setCharacters" via PROPS     │
├─────────────────────────────────────────────────────────┤
│  SERVICE LAYER:    src/service/Service.js               │
│  (simulated CRUD + data from src/data/Characters.json)  │
│  └─ network utility (obsolete) → src/service/Api.js     │
├─────────────────────────────────────────────────────────┤
│  SHARED COMPONENTS LAYER:  src/components/*             │
│  (Header, NavigationBar, Footer, Loading, iu/iconMessage)│
├─────────────────────────────────────────────────────────┤
│  STYLE LAYER:    src/components/layout/*.css + iu/*.css │
├─────────────────────────────────────────────────────────┤
│  STATIC ASSETS LAYER:  src/assets/*   and   public/*    │
└─────────────────────────────────────────────────────────┘
```

Rule of the current architecture: **`App.jsx` is the single source of truth**. The `characters` state lives there and flows down to the views via props; views modify it exclusively through `setCharacters` (a function that "lifts" the change up). The files in `service/` are the only gateway between the views and the data (today from `src/data/Characters.json` with simulated latency).

## 3. Detailed File-by-File Description

### 3.1 Project root

#### 📄 `index.html`
- **Layer:** Entry (browser entry point).
- **Role in the architecture:** It is the very first thing the browser loads. Vite uses it as the template for the build.
- **What it does:**
  - Defines the `<div id="root">`, the container where React mounts the whole app.
  - Loads **Bootstrap 5.3 via CDN** (CSS in `<head>`, JS bundle before the closing `<body>`) — that's why every view uses classes like `card`, `container`, `navbar`, etc. without Bootstrap being installed as an npm dependency.
  - References the favicon `public/harry-potter-icon.webp`.
  - Loads the React code with `<script type="module" src="/src/main.jsx">`.
- **Connections:** `main.jsx` (the script that mounts the app).

#### 📄 `package.json`
- **Layer:** Configuration.
- **What it does:**
  - Defines the name `harry-potter-page` and the module type (`"type": "module"`).
  - **Scripts:**
    | Script | Command | Purpose |
    |---|---|---|
    | `dev` | `vite` | Development server with HMR |
    | `build` | `vite build` | Generates `dist/` for production |
    | `preview` | `vite preview` | Previews the build locally |
    | `lint` | `eslint .` | Analyzes the code with ESLint |
  - **Key dependencies:** `react`, `react-dom`, `react-router-dom` (routing), `sweetalert2` (popups). *(Note: `opencode-ai` appears as a dependency but it is not used anywhere in the code.)*
  - `"homepage": "https://t1629.github.io/Harry-Potter/"` — reflects the GitHub Pages destination.

#### 📄 `vite.config.js`
- **Layer:** Build configuration.
- **What it does:**
  - Activates the official React plugin (`@vitejs/plugin-react`, Oxc-based) to transpile JSX and enable HMR.
  - **`base: "/Harry-Potter/"`**: CRITICAL for GitHub Pages. Makes every asset, route and build use that prefix. Changing it would break the GitHub Pages deployment.
- **Connections:** It must match the `basename="/Harry-Potter"` in `main.jsx`.

#### 📄 `eslint.config.js`
- **Layer:** Code quality.
- **What it does:** Uses ESLint flat config with:
  - `@eslint/js` recommended (base JS rules).
  - `eslint-plugin-react-hooks` recommended (validates correct usage of `useState`, `useEffect`, etc.).
  - `eslint-plugin-react-refresh` (vite) (component export rules for HMR).
  - Ignores `dist/`.
  - Browser globals (that's why `window`, `document`, etc. don't raise errors).

#### 📄 `.gitignore`
- Excludes `node_modules/`, `dist/`, logs and editor files. Prevents committing builds and dependencies to the repo.

#### 📄 `.github/workflows/deploy.yml`
- **Layer:** CI/CD.
- **What it does (step by step) on every `push` to the `main` branch:**
  1. `actions/checkout@v4` — downloads the code.
  2. `pnpm/action-setup@v3` with version 9 — installs pnpm.
  3. `actions/setup-node@v4` with Node 20 and pnpm cache.
  4. `pnpm install` — installs dependencies.
  5. `pnpm run build` — generates `dist/`.
  6. `actions/upload-pages-artifact@v3` — uploads `dist/` as an artifact.
  7. `actions/deploy-pages@v4` — publishes the artifact to GitHub Pages.
- **Permissions:** `contents: read`, `pages: write`, `id-token: write` (required for Pages).

### 3.2 `src/` — Entry and routes

#### 📄 `src/main.jsx`
- **Layer:** React entry point.
- **What it does:**
  - `createRoot(document.getElementById("root")).render(...)` — mounts React into the `#root` of `index.html`.
  - Wraps the app in **`BrowserRouter` with `basename="/Harry-Potter"`**:
    - That's why `<Link>` elements can use `/Listado` without writing the prefix everywhere.
    - It must ALWAYS match the `base` in `vite.config.js`.
  - Activates `StrictMode` (detects double side effects during development).
- **Connections:** `App.jsx`, upstream to `index.html`.

#### 📄 `src/App.jsx`
- **Layer:** Routes + Global state + Global layout. **It is the heart of the application.**
- **Global state:** `const [personajes, setPersonajes] = useState([])`.
  - It is the project's **single source of truth**: the whole character list lives here.
  - It flows down to the views as props (`personajes`) and can only be modified through `setPersonajes`, passed down as props (lifting state up).
- **Global layout:** Renders `<Header />`, `<NavigationBar />`, the `<Routes>` and `<Footer />` inside the `hp-container` wrapper.
- **Declared routes table:**

  | Route | View | Props received |
  |---|---|---|
  | `/` | `Home` | (none) |
  | `/Listado` | `List` | `personajes`, `setPersonajes` |
  | `/Detalle/:id` | `Read` | `personajes` |
  | `/EditarPersonaje/:id` | `Edit` | `personajes`, `setPersonajes` |
  | `/CrearPersonaje` | `Create` | `personajes`, `setPersonajes` |
  | `/Eliminar/:id` | `Remove` | `personajes`, `setPersonajes` |
  | `*` (anything else) | `NotFound` | (none) |

- **Imports** `./components/layout/App.css` for the global container styling.
- **Connections:** points to the 7 views + the 3 layout components.

### 3.3 `src/data/` and `src/service/` — Data layer

#### 📄 `src/data/Characters.json`
- **Layer:** Local data (the source of truth for the base characters).
- **Origin:** copy of the `data` folder from a GitHub repository containing the characters' JSON data. It was created because the fake API `https://hp-api.onrender.com` was **suspended by its creators**.
- **Content:** an array of ~400 objects with the Harry Potter universe characters: `id` (original UUID), `name`, `species`, `gender`, `house`, `wand`, `patronus`, `actor`, `image`, etc.
- **Note:** user-created characters do NOT live here; they only live in the state of `App.jsx` (see data flow).

#### 📄 `src/service/Api.js`
- **Layer:** Network utility (⚠️ **OBSOLETE**).
- **What it does:**
  - Exports by default the async function `fetchHp(url, options)` which performed a `fetch` to a URL and parsed the JSON with error handling.
  - It was the utility `Service.js` used when the source was the external API.
- **Current status:** `Service.js` still imports it (`import fetchHp`) but **no longer calls it** (data now comes from the local JSON). It is kept untouched by project decision; it could be useful if a real API is connected again in the future.

#### 📄 `src/service/Service.js`
- **Layer:** Domain services (simulated CRUD).
- **Data source:** imports `src/data/Characters.json` with the `personajes` alias.
- **Network simulation:** every operation is `async` and simulates API latency with `setTimeout` wrapped in a promise: **500ms** in `GetAll`, **300ms** in the rest. It is not a real API and has no persistence: the simulation only covers the *latency* of the call.
- **The 5 exported functions:**

  | Function | What it does | Does it touch real data? |
  |---|---|---|
  | `GetAll()` | Waits 500ms and returns the JSON array with `id: index` added to every character (the original UUID from the JSON is replaced by a positional id 0..N, which is the one the whole app uses). | Simulated over local JSON |
  | `GetCharacter(id, personajes)` | Waits 300ms and returns with `find` the character from the in-memory array with `id === parseInt(id)`. Returns `undefined` if not found. | Simulated (memory) |
  | `CreateCharacter(data, personajes)` | Waits 300ms and builds a new character with `id: Date.now()`, returning `[...personajes, newCharacter]`. | Simulated (memory) |
  | `EditCharacter(id, data, personajes)` | Waits 300ms and returns the **full updated array**: replaces the character with `id === parseInt(id)` with `{ ...p, ...data }`. ⚠️ New signature: `(id, data, personajes)`; it used to be `(id, personajes)` and returned a single character. | Simulated (memory) |
  | `RemoveCharacter(id, personajes)` | Waits 300ms and returns the **filtered array** without the character (`filter` with `p.id !== parseInt(id)`). ⚠️ It changed: it used to return a single element (with the inverted `find` bug); now it returns the list without the character. | Simulated (memory) |

- **Important detail about the `id`s:**
  - Characters coming from the JSON get `id: 0, 1, 2, ...` (positional index, assigned in `GetAll`).
  - Characters created by the user get `id: Date.now()` (a large number, > 1000).
  - `List.jsx` takes advantage of this to tell them apart (see below).

### 3.4 `src/page/` — Views

#### 📄 `src/page/Home.jsx`
- **Route:** `/`
- **Layer:** Welcome view (landing page).
- **What it does:**
  - Renders the title "⚡ Bienvenido a la magia" and a welcome paragraph.
  - Displays a wand image (`assets/pngwing.com4.png`) with the `.varita` class.
  - Uses no state and no props; it is purely presentational.
- **Imports:** `assets/pngwing.com4.png` and `components/layout/Home.css` (its styles).

#### 📄 `src/page/List.jsx`
- **Route:** `/Listado`
- **Layer:** Main CRUD view (read all + navigation).
- **Props:** `personajes`, `setPersonajes`.
- **Internal state:** `loading` (boolean) to show the spinner.
- **What it does, step by step:**
  1. In the `useEffect` (with `[]`, i.e., only on mount):
     - Sets `loading = true`.
     - If `personajes.length === 0` (no data yet), calls `await GetAll()` from the service (500ms simulated delay over the local JSON) and stores the result with `setPersonajes` (lifting the state up to `App.jsx`).
     - In the `finally` block, turns `loading` off.
     - Catches errors with `console.error`.
  2. **The `personajesLimit` filter** combines:
     - The first **22 characters** from the API (`slice(0, 22)`), and
     - Every **user-created** character (those with `id > 1000`, i.e., `Date.now()` ids).
     - This avoids listing hundreds of API characters: only the first 22 + the user's own ones are shown.
  3. Renders a **Bootstrap grid (`row` / `col-md-3`)** of cards (`.card-magica`), one per character, showing: image, name, species, gender and house.
  4. Each card has **3 link-buttons**:
     - `Detalles de {name} ⚡︎` → `/Detalle/{id}` (Read)
     - `Editar a {name} 🪄` → `/EditarPersonaje/{id}` (Edit)
     - `Eliminar a {name} 💀` → `/Eliminar/{id}` (Remove)
  5. While `loading` is `true`, it renders `<Loading />` instead.
- **Imports:** `Service.GetAll`, `Loading`, `list.css`.
- **Note about the limit:** the original API shipped ~400 characters, which is why the `slice(0, 22)` existed; the local JSON keeps all the characters and the limit still works the same way.

#### 📄 `src/page/Read.jsx`
- **Route:** `/Detalle/:id`
- **Layer:** Detail view (CRUD - Read).
- **Props:** `personajes`. **Internal state:** `info` (the character), `error` (boolean).
- **What it does:**
  1. Reads the `:id` from the URL with `useParams()`.
  2. In a `useEffect` (with `[id, personajes]`), calls `GetCharacter(id, personajes)` and stores the result in `info`.
  3. On error → renders `<Error />` (which is `ErrorMessage.jsx`).
  4. If there is no data yet → shows "Cargando personaje..." (⚠️ see issue #2 in section 5: if the id doesn't exist, `GetCharacter` returns `undefined` and it keeps loading forever without showing the popup).
  5. If data exists → renders a centered card (`.card-detail`) with image, name, species, gender and house, plus a "Volver al listado" button (`/Listado`).
- **Imports:** `GetCharacter`, `ErrorMessage`, `Read.css`, `buttom.css`.

#### 📄 `src/page/Create.jsx`
- **Route:** `/CrearPersonaje`
- **Layer:** Creation view (CRUD - Create). **The most complex one in terms of state handling.**
- **Props:** `personajes`, `setPersonajes` (⚠️ although it also declares `loading` and `error` in its signature, `App.jsx` never passes them, so they are always `undefined`).
- **State with `useReducer` (instead of `useState`):**
  - `initialState`: `{ Imagen: "", Nombre: "", Especie: "", Genero: "", Casa: "" }`.
  - `personajeReducer`: a `switch` with 5 actions (`SET_IMAGEN`, `SET_NOMBRE`, `SET_ESPECIE`, `SET_GENERO`, `SET_CASA`), each one updating a single form field with `action.payload`.
- **Flow on submit (`handleSubmit`):**
  1. `e.preventDefault()` (avoids the native submit).
  2. Builds an object **translating the form's Spanish field names into English** (the ones used by the API/state): `Imagen → image`, `Nombre → name`, `Especie → species`, `Genero → gender`, `Casa → house`.
  3. Assigns `id: Date.now()` (it does NOT use `Service.CreateCharacter`! It builds the object directly in the view).
  4. `setPersonajes([...personajes, nuevo])` — appends to the global state and navigates to `/Listado` with `useNavigate`.
- **Render:** shows a Sorting Hat image and a Bootstrap form with a "golden parchment" style (inline gradient styles).
- **Imports:** `assets/pngwing.comS.png` (Sorting Hat).

#### 📄 `src/page/Edit.jsx`
- **Route:** `/EditarPersonaje/:id`
- **Layer:** Editing view (CRUD - Update).
- **Props:** `personajes`, `setPersonajes`. **Internal state:** `infoP` (the edited fields), `originalName` (for the title), `error`, `loading`.
- **What it does (fixed flow — it used to have the bug that threw an error while editing):**
  1. Reads `:id` from the URL with `useParams`.
  2. In the `useEffect` (`[id, personajes]`), looks up the character with `GetCharacter(id, personajes)` (returns **a single character**, 300ms simulation):
     - If `undefined` comes back → sets `error = true` (renders `<Error />`).
     - If it exists → loads its 5 fields (`image`, `name`, `species`, `gender`, `house`) into `infoP` and its name into `originalName`.
     - In the `finally` block it turns `loading` off (meanwhile it renders `<Loading />`).
  3. Every `<input>` is controlled: `value={infoP.xxx}` + an `onChange` that calls `setInfoP({ ...infoP, field: val })`.
  4. `handleSubmit` (async):
     - Calls the service with the **new signature**: `await EditCharacter(id, infoP, personajes)` → returns the full array with the character already updated.
     - `setPersonajes(nuevos)` and `backPage("/Listado")` (the changes are reflected in the list).
  5. The "Cancelar" button → goes back to `/Listado` without saving.
  6. On `error` → renders `<Error />`.
- **Imports:** `GetCharacter` (load) and `EditCharacter` (save), `ErrorMessage`, `Loading`.

#### 📄 `src/page/Remove.jsx`
- **Route:** `/Eliminar/:id`
- **Layer:** Delete confirmation view (CRUD - Delete).
- **Props:** `personajes`, `setPersonajes`. **Internal state:** `personajeHP` (the character to delete), `error`.
- **What it does (fixed flow — it used to not show the data of the selected character):**
  1. Reads `:id` with `useParams`.
  2. In the `useEffect` (`[id, personajes]`) it calls `GetCharacter(id, personajes)` to **display** the character in the confirmation screen (returns a single character, 300ms simulation):
     - If it is `undefined` → `error = true` (renders `<Error />` instead of an infinite Loading).
     - If it exists → stores it in `personajeHP` (keeps a `console.log(response)` for debugging).
  3. While `personajeHP` is `undefined`, it renders `<Loading />`.
  4. `confirmar()` (async) — the REAL deletion:
     - `await RemoveCharacter(id, personajes)` → the service returns the **filtered array** without the character.
     - `setPersonajes(nuevos)` and navigates to `/Listado`.
  5. `cancelar()` — navigates to `/`.
  6. Render: confirmation alert ("¿Estás seguro que deseas eliminar a este mago?"), the wizard image (`assets/pngegg.png`), the character's data, and two buttons: "Avada Kedavra 💀" (confirm) and "❌ Cancelar".
- **Imports:** `GetCharacter` (display) and `RemoveCharacter` (delete), `Loading`, `ErrorMessage`, `assets/pngegg.png`, `remove.css`.

#### 📄 `src/page/NotFound.jsx`
- **Route:** `*` (catch-all in `App.jsx`).
- **Layer:** Themed 404 view.
- **What it does:**
  - Themed text ("the page has vanished like a misfired spell"), Ministry of Magic image (`assets/notFoundImage.png`), and a link-button "Volver a Hogwarts" → `/`.
- **Imports:** `Link` from react-router-dom, `notFound.css`, `assets/notFoundImage.png`.

#### 📄 `src/page/ErrorMessage.jsx`
- **Layer:** Reusable error popup (it is not a route; it is used by `Read`, `Edit` and `Remove`).
- **What it does:**
  - Directly fires `Swal.fire(...)` (SweetAlert2) with:
    - Title "Harry Potter", text "Personaje no encontrado..." and injects the **ASCII art** from `components/iu/iconMessage.jsx` into the popup's HTML.
    - A "Volver al listado" button.
  - When the popup is confirmed (`.then()`), it navigates to `/Listado` with `useNavigate`.
  - ⚠️ Technical detail: it invokes `Swal.fire` **in the component body**, i.e., as a direct side effect of the render (see issue #4, section 5).
- **Connections:** used by `Read.jsx`, `Edit.jsx` and `Remove.jsx`.

### 3.5 `src/components/` — Shared components

#### 📄 `src/components/Header.jsx`
- **Layer:** Global layout component.
- **Renders:** the "⚡" logo, the title "Hogwarts Mistery", a subtitle with a magic underline, and the 4 Hogwarts houses as colored chips (`.house.gryffindor`, `.slytherin`, `.ravenclaw`, `.hufflepuff`).
- **Connections:** styles in `components/layout/Header.css`; rendered by `App.jsx` on every route.

#### 📄 `src/components/NavigationBar.jsx`
- **Layer:** Global navigation component.
- **Renders:**
  - A Bootstrap navbar (`.navbar-expand-lg`) with the logo (image `assets/pngwing.com.png`) linking to `/`.

## 4. Data Flow

### 4.1 Startup flow

```
Browser
   │
   ▼
index.html (Bootstrap via CDN + #root + main.jsx script)
   │
   ▼
main.jsx → BrowserRouter (basename="/Harry-Potter") + StrictMode
   │
   ▼
App.jsx → creates the global state "personajes" = []
   │
   ▼
Decodes the URL → renders the matching view + Header/Nav/Footer
```

### 4.2 Data loading flow (the first time the user enters /Listado)

```
List.jsx (mounts)
   │  useEffect: personajes.length === 0 ?
   ▼
Service.GetAll()                     ← service layer
   │  setTimeout 500ms (latency simulation)
   ▼
src/data/Characters.json (import alias)  ← local data (ex external API)
   │  data → data.map((p, i) => ({...p, id: i}))
   ▼
setPersonajes(data)                  ← LIFTS the state up to App.jsx
   │
   ▼
App.jsx re-renders → List receives personajes → cards are painted
```

If the user reloads the page, the global state resets to `[]` and `List` fetches the data from the service again (new 500ms simulation over the JSON). If they navigate to another view and come back to `/Listado` without reloading, the `useEffect` doesn't fetch anything again because `personajes.length !== 0`.

### 4.3 Flow of a "write" operation (Create / Edit / Remove)

```
View (Create/Edit/Remove)
   │  handleSubmit / confirmar
   ▼
Service.CreateCharacter / EditCharacter / RemoveCharacter
   │  setTimeout 300ms (latency simulation)
   ▼
returns the new array (append / update / filter)
   │
   ▼
setPersonajes(newArray)       ← modifies App.jsx's state
   │
   ▼
useNavigate("/Listado")       ← redirects
   │
   ▼
List.jsx re-renders with the new array (it doesn't fetch again: length > 0)
```

⚠️ **Important:** writes DO NOT travel to any API. Everything lives in the browser's memory (React state) and **is lost on reload**. By project decision NO persistence will be added: this is a **simulation of an API call**, not a real API (see restrictions).

### 4.4 Current prop drilling

`personajes` / `setPersonajes` flow down from `App.jsx` → (views). Right now there is only one level, so the props pattern works fine. If the app grew (more nested views, more global states), it would be worth migrating to Context API or React Query (see suggestions).

## 5. ⚠️ Detected Issues (status and description)

### Issue #1 — ✅ RESOLVED: `RemoveCharacter` bug and `Remove.jsx` bug
- **It was:** `RemoveCharacter` used `find` with the inverted condition (`p.id !== parseInt(id)`) and returned almost always the first character; because of that, `Remove.jsx` did not display the selected character's data in the confirmation screen.
- **Status:** RESOLVED in two parts:
  1. The service now performs a correct `filter` and returns the **array without the character**.
  2. `Remove.jsx` now loads the character to display with `GetCharacter(id, personas)` and deletes using the array returned by `RemoveCharacter` in `confirmar()`. If the character doesn't exist it renders `<Error />` instead of an infinite Loading.

### Issue #2 — 🟡 PENDING: `Read.jsx` shows "Loading..." forever if the id doesn't exist
- **Where:** `src/page/Read.jsx` (root cause in `Service.js` → `GetCharacter`).
- **Problem:** `GetCharacter` uses `find`, which returns `undefined` when there is no match. In `Read.jsx`, the `useEffect` calls `GetCharacter` and only enters the `catch` if it **throws an exception** (but `find` doesn't throw...), so `info` stays `null` and "Cargando personaje..." renders forever, **without** showing the `ErrorMessage` popup.
- **Impact:** if the user enters `/Detalle/9999` (nonexistent id), they see an infinite loading state.
- **Note:** `Edit.jsx` and `Remove.jsx` already handle this case (`if (!response) setError(true)`); `Read.jsx` should mimic them.
- **Conceptual fix:** in `Read.jsx`, check `if (!data) → show error / ErrorMessage`, or make the service throw an exception when the character is not found.

### Issue #3 — ⛔ NOT APPLICABLE: data persistence
- **Context:** the CRUD has no persistence; everything lives in the browser's memory and is lost on reload.
- **Project decision (restriction):** NO persistence (localStorage/backend) will be added. The app is a **simulation of an API call**, not a real API; the "base data + in-memory state" behavior is intentional. This issue is closed as "not applicable".

### Issue #4 — 🟠 `ErrorMessage.jsx` fires `Swal.fire` during render
- **Where:** `src/page/ErrorMessage.jsx`.
- **Problem:** `Swal.fire(...)` is invoked in the component body (not in a `useEffect`). A component's render should not have side effects: under `StrictMode` in development React mounts/unmounts twice, and in future versions this will behave differently. It is fragile.
- **Conceptual suggestion:** move the call into a `useEffect(() => { Swal.fire(...).then(() => navigate(...)) }, [])`.

### Issue #5 — 🟠 `Create.jsx` declares props it never receives (and doesn't use its own service)
- **Where:** `src/page/Create.jsx`.
- **Problems:**
  1. Signature: `({ personajes, setPersonajes, loading, error })` — but `App.jsx` only passes `personajes` and `setPersonajes`; `loading` and `error` are always `undefined` (the render has `loading`/`error` branches that never trigger).
  2. The view **does not use** `Service.CreateCharacter`: it manually builds the new object with `id: Date.now()` (duplicating logic already existing in the service, leaving it unused).
- **Conceptual suggestion:** remove the ghost props and use (or remove) `CreateCharacter`.

### Issue #6 — 🟢 Minor / naming issues
- Folder `src/components/iu/` — it would normally be `ui` (non-critical typo).
- Mixed CSS names: `list.css` vs `Read.css` / `Home.css` (consistency between `lowercase` and `PascalCase`).
- `opencode-ai` sits in `package.json` `dependencies` but is never used in the code.
- `src/service/Api.js` became obsolete (kept by project decision, documented in 3.3).
- `src/assets/harry-potter-page.html` + `harry-potter-page_files/` is reference junk that should be moved out of `src/` (or into a `docs/` folder) to keep the build clean.
- In `index.html` the tag says `lang="en"`, but the whole UI is in Spanish (it should be `lang="es"`).
- `Documentation.txt` (written by the author) already records: separating logic/design/components for scalability and improving the "not found" popup to a dark style.

## 7. Quick Glossary

| Term | Meaning in this project |
|---|---|
| `personajes` | Array of objects (image, name, species, gender, house, id) living in `App.jsx` |
| `setPersonajes` | The only way to modify that array (flows down from `App.jsx` to the views via props) |
| `Characters.json` | Local copy of the characters data (ex suspended external API); lives in `src/data/` |
| `positional id` | id 0..N assigned to characters coming from the JSON (`Service.GetAll`) |
| `Date.now() id` | Large id (>1000) of user-created characters; `List.jsx` uses it to tell them apart from JSON ones |
| API simulation | `setTimeout` (500ms/300ms) in `Service.js` to simulate the latency of an API call |
| Lifting state up | React pattern of raising the state to the closest common ancestor (`App.jsx`) and passing it down via props |
| Prop drilling | Passing props through several levels (in this project: just `App.jsx` → views) |
| Base path | `/Harry-Potter/`: prefix in Vite (`base`) and in the Router (`basename`), required for GitHub Pages |
